The system behind it

The console I use to direct my agent team.

When agents ship faster than I can read, my attention becomes the scarce resource. I built the console to spend it on my goals first.

I run a team of AI agents across several products: a staff PM, QA, an engineer, a UX reviewer, privacy and security, and positioning. By October their pull requests and handoff notes arrived faster than I could read them, and I was losing hours to work that felt urgent but served no goal.

Open the Studio Console

The live page shows real numbers. In its first week, most of my agents' work matched no goal, which is the problem it exists to catch. Job-search progress is kept private.

What it shows

  • Focus: my three or four goals, where this week's effort went, and any work that served no goal, flagged as a possible rabbit hole.
  • Call Sheet: everything waiting on my decision, each reduced to one step.
  • Build Slate: each product's stage and health.
  • Horizon Board: milestones in Now, Next, Later and Done.
  • Agent Roster: which agents ran on each pull request and whether it passed its gates.

How it works

The page rebuilds every hour from the studio's public GitHub repos: each product's HANDOFF.md, its open pull requests, intake issues and agent run logs. It has no database and no login. I built it for one job, a product owner directing an agent team, so it has no team accounts or permissions.

It went live on October 31 with a success test set in advance: five weekdays in a row run from the Call Sheet without opening a handoff file. If that hasn't happened by November 14, I'll change it or retire it.

What it replaced

Before the console I ran two small apps, Build Slate and a near-term roadmap. Both were organized by product. Neither showed whether the week's work served a goal or which calls were waiting on me. Their sample-data demos are still up: Build Slate and the roadmap.

Source for the console, both earlier apps and the PM templates below is on GitHub.

Decisions that leave a trail

  • Decision log: every call records why, and what it beat.
  • Persona check: before a product decision is final, each persona gets a green or red with a one-line reason. CI fails if a decision file skips it.
  • Anchors: a few principles every feature is checked against, like "anxiety-less" and "stays on US soil."
  • Post mortems: each one adds a rule, so the same mistake doesn't happen twice.

The team it directs

Each agent owns one lane, every repo keeps a handoff file, and nothing ships without my review. The story of how the studio came together.
