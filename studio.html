The studio behind the work

I stopped prompting chats and started running a studio.

Every product here began as one conversation with an AI. Five products later, I was the only thing connecting them. This is how that turned into a small studio: agents with lanes, a coordinator above them, and me in the product owner's seat.

One chat per product

It started simply: open a chat, describe a problem from my own life, get a working page that evening. It worked so well that I kept going, and that's where it broke. Each chat forgot what the others knew. I was re-explaining rules, copying decisions between windows, and finding that two chats had solved the same problem two different ways. The AI wasn't the bottleneck. I was, because I was the only memory.

Specialists with lanes

The first fix was borrowed from every good product team: give each role one job. I wrote down the agents I kept recreating by hand, made them generic, and put them in one shared library that every repo syncs from.

  • Staff PM: starts from the bet, writes testable criteria, cuts scope, and runs go/no-go gates.
  • QA (tests first): turns each criterion or bug into a failing test before anyone writes a fix.
  • Engineer: makes that test pass in one small, reversible PR, and never merges or deploys on its own.
  • UX reviewer: reviews every screen and word as the least tech-savvy person who will use it, on a real phone width.
  • Privacy and security: holds each product to its own promise, like "logs never leave the laptop" or "photos never leave the phone".
  • Positioning: keeps a register of what's true today, so no page or post claims more than the product does.

None of them names a product. Each one reads the repo it's working in first: its hard rules, its story and its current state. So the same staff PM works on a kids' bedtime app and an energy CLI, and improving one agent improves it everywhere. In the family photo app, that review loop caught a co-parent data leak before any real user saw it.

A coordinator, not another builder

The bigger move was deciding that one project should build nothing. Each product now has its own project that does its own coding. Above them sits a coordinator, the product studio, whose only job is the view across all of them: what moved, what stalled, what needs me, and where the portfolio stands.

It felt like the most grown-up decision in the whole effort. It's the same move a PM makes when a team outgrows one person's head: stop doing the work yourself and build the system that keeps the work honest.

The operating system around it

  • One handoff file per repo. Every repo keeps a HANDOFF.md: what's done, what's in progress, the exact next step, and what's blocked. Every session reads it first, and a check fails any pull request that makes progress without updating it.
  • One status list across the studio. A single page lists what's done and what's waiting on me. If it's done, no agent asks again. If it's waiting, no agent re-asks.
  • The repo decides who owns the work. A change to a product's repo belongs to that product's project. Anything else goes to the studio. A project that needs a change it doesn't own writes a short intake, and the owner does the work. I don't have to make that call.
  • Overnight shifts. Each product runs an unattended build at 2:15am, timed just after my usage limit resets. One night took ccwatts from a log parser to a working dashboard and playground in seven small PRs.
  • A morning digest. At 6:30 I read one short summary: what shipped overnight, what's blocked, and the one thing that needs me today.
  • A story log. Every notable call goes into a running log as it happens, which is where this page came from.

My job became the product owner

I don't review the code line by line. I review the pull request descriptions: what changed and why, how it was tested, and which decision is mine. The agents write them for that reader, so a good description is part of the work, not an afterthought.

Nothing reaches a live site or a user without me. Agents open draft pull requests and stop. My evenings went from typing prompts to making calls: approve, cut, or send it back with one sentence. In one recruiter-ready sprint, three review rounds found 21 issues in ccwatts, and every one was fixed test-first across eight small draft PRs before I woke up.

What it taught me

  • Rules in files beat rules in my head. A hard rule written once in the repo is followed by every session. One I only say in chat is forgotten by the next.
  • One source of truth per thing. When status lived in three places, it drifted in three directions.
  • Ask the human once, in one step. My time is the scarcest resource in the studio, so every ask is a link, a paste box or a one-word choice.
  • Honest beats impressive. Agents say "untested" when they couldn't check something, and sample data says so everywhere.
